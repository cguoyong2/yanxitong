# v0.2.0-p1-hardening Release Notes

Date: 2026-06-22

Tag: `v0.2.0-p1-hardening`

## Release Type

P1 launch hardening release for the accepted MVP baseline.

This release is suitable for local acceptance, pilot preparation and technical review. It is not a full production payment launch because formal WeChat service-provider/sub-merchant onboarding and real callback validation are intentionally deferred.

## Included

### Export Hardening

- Added automated row-cap and entitlement-denial coverage for gift, RSVP and favor exports.
- Made export row cap configurable through `config_item` key `export.max_rows`.
- Added predictable oversized-export rejection before workbook generation.
- Improved admin export loading and error handling.

### Payment Readiness

- Added `PaymentProviderReadinessService` to block real-provider order creation when provider configuration is incomplete.
- Added admin launch-readiness visibility for payment provider fields without exposing secrets.
- Expanded callback tests for invalid signature, parse failure, duplicate event, amount mismatch, non-success trade state and duplicate paid callbacks.
- Added WeChat callback fixture redaction policy and placeholder fixture folder.

### Miniapp Dependency Security

- Recorded current `npm audit` baseline in `docs/miniapp-dependency-security-audit.md`.
- Kept current uni-app toolchain unchanged because automatic `npm audit fix --force` proposes breaking changes.
- Preserved reproducible `uni build -p mp-weixin` output.

### Public Invitation And Share Hardening

- Added readable invalid-share-link and missing-banquet public errors.
- Added disabled/deleted template fallback using preset-based base invitation rendering.
- Added miniapp loading, error, retry and disabled-entry states.
- Added public invitation smoke coverage for missing cover, unavailable template, disabled entries and missing slug.
- Documented `shareSlug`, `banquetId`, `invitationId`, `entrySource` and public action URL behavior.

## Known Limits

- Real WeChat service-provider/sub-merchant onboarding is not included.
- Real payment callbacks still require provider-side staging validation.
- Agent, hotel and wedding-company independent workspaces are not included.
- Complex visual invitation editor is not included.
- Device inventory scheduling, deposit, repair and return flows are not included.
- Real cloud speaker hardware protocol is not included.

## Pre-Launch Manual Checklist

- Confirm production secrets are replaced: admin password, DB password, Redis password and callback secrets.
- Set `PAYMENT_MOCK_SUCCESS_ENABLED=false` outside local acceptance.
- Configure payment provider adapter through environment/config, not business services.
- Run strict readiness in production-like environment:

  ```bash
  REQUIRE_READINESS_READY=1 bash deploy/scripts/release-readiness.sh
  ```

- Validate HTTPS, ingress, domain, callback URL and deployment-level rate limits.
- Import `miniapp/dist/build/mp-weixin` into WeChat DevTools after any miniapp dependency change.
- Keep callback logs, payment orders, gift records, favor entries, broadcast logs and operation logs auditable during pilot.
